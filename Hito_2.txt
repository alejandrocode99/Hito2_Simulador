Build a plataform simulated ECU with seperated responsabilites
-----------------------------------------------------------------------------------

System will hace two units:
    - Gateway ECU: validate car signals
    - Control ECU: take decitions based on valid signals

Studen should implement:
    * 5 signals manual entry via std::cin
    * Valid range check
    * Compare against reference values
    * 6 states state machine
    * Clear diagnostic messages

General Architecture
┌────────────────────────────┐  Input Values  ┌──────────────────────────┐ Valid Signals  ┌───────────────────────────┐
│ Manual input signal values ├───────────────>│ Gateway validate signals ├───────────────>│ Control ECU decides state │
└────────────────────────────┘                └──────────────────────────┘                └───────────────────────────┘

Key aspects on eeach unit:
 - Gateway ECU: Can signal be trusted?
 - Control ECU: Wich decitions should I take?

 Signal         Units   Min     Max     Example
 Speed          km/h    0       250     80
 RPM            rpm     0       8000    2500
 Temperature    C       -40     150     90
 Throttle       %       0       100     35
 Battery        V       9       16      13.8

 Note: This ranges are foe educative purposes only. Gateway ECU simulatin will use them to accept o reject a signal.

 Gateway ECU Duties
 - Data must be read correctly
 - Signal value should be into the range described by Min and Max values
 - Check signal availability or abcense
 - No invalid conditions for instance: Speed in Max value wityh low RPM and low Throttle values or High RPM with low Throttle value.

 Control ECU duties
 - Check signal values against reference values
 - Warning detection
 - Critical condition detection
 - Checks coherence between related signals
 - Changes system state

 Eg: If Temperature signal read is 115C, Control ECU detets overheating and changes to a SAFE_STATE

 Signal         Normal              Warning                 Critical
 -----------------------------------------------------------------------------------------
 Temperature    <100C               100C to 110C            >110C
 RPM            Upto 6000rpm        Higher than 6000rpm     Over 7000rpm
 Battery        12V to 16V          11V to 12V              <11V
 Throttle       RPM coherent        Minor inconsistency     High inconsistency
 Speed          RPM coherent        Minor inconsistency     High inconsistency


 Signal validation code example:
1 bool validateSpeed(double value)
2 {
3     return value >= 0.0 && value <= 250.0;
4 }
5
6 bool validateTemperature(double value)
7 {
8     return value >= -40.0 && value <= 150.0;
9 }
10
11 bool validateVoltage(double value)
12 {
13   return value >= 9.0 && value <= 16.0;
14 }

A Warning makes system into DEGRADED state
A critical condition amkes system SAFE_STATE

INIT Variable initialisation and Config
SELF_TEST Before start systems test itself
OPERATIONAL All signals valid and in range
SAFE_STATE At least one critical condition
SHUTDOWN System controled shutdown

State enum code example:
1 enum class ECUState {
2    INIT,
3    SELF_TEST,
4    OPERATIONAL,
5    DEGRADED,
6    SAFE_STATE,
7    SHUTDOWN
8 };

Decision logic example code:
1 if (criticalCondition) {
2   state = ECUState::SAFE_STATE;
3 }
4 else if (warningCondition) {
5    state = ECUState::DEGRADED;
6 }
7 else {
8    state = ECUState::OPERATIONAL;
9 }

Priority: A critical condition is higher priority over a warning.

Combined signal evaluation

Control ECU can and should check for coherence between signals.
Examples:
    * >0km/h Speed and RPM = 0
    * High Throttle and low RPM values
    * High Temperature with a low Battery Voltage
    * High RPM with low Throttle value

Not all failures relay in only one signal value.


Program Flow:
1 System Init
2 Change to SELF_TEST state
3 Self test execute
4 While user does not exit:
5 Ask for Speed value
6 Ask for RPM value
7 Ask for Temperature value
8 Ask for Throttle value
9 Ask for Battery Voltage value
10 Gateway ECU validates signals
11 Control ECU evaluate against reference values
12 Display curret state after signal processing
